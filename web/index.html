输出（A/B 可同时启用）

          

            
            
            
            
          

          

            
            
            
            
          

        


        

          
          
          
        

        

          条件示例：

          · 对话框文本 包含 “游泳” → A 通道 35 / 呼吸 / 3 秒

          · 战斗播报 正则 “今天天气怎么样|你吃了吗” → A 70 / 持续 / 3 秒

          · 变量 ≥ 80（选 estrus）→ B 50 / 潮汐 / 0 秒（持续到条件结束）



          “和”与“或”怎么写：

          · 或（任意一个满足就触发）：正则里用 |，
            例如 今天天气怎么样|你吃了吗 表示出现“今天天气怎么样”或“你吃了吗”都触发；
            高级表达式里也可以用 ||。

            · || 可以同时引用不同来源：左边是对话框文本，右边是战斗播报 ID，任意一个成立就触发。

          · 和（必须同时满足）：请把来源切到“高级表达式”，用 &&，
            例如 mapId === 63 && swimming、
            estrus >= 80 && lust >= 50。

          · 简单条件一次只能判断一个来源；要“和”就必须用高级表达式。

          · “包含”是纯文本包含；“正则”里的 | 才是“或”。
            要匹配真正的竖线字符，写成 \|。



          文字检测来源：

          · 对话框文本：角色对话内容（含角色名）

          · 战斗播报：战斗左上角 Ticker 文本

          · 战斗日志：Window_BattleLog（敌人行动/伤害/状态）

          · 播报 ID：语义 ID（如 TrapActive），比关键词更稳定

          · OCR 文本：仅 OCR 模式可用，只支持“包含 / 正则”


          注：使用浏览器一键翻译页面后，页面示例中的部分符号（如 |、\、&&）
          可能丢失或被改写；刷新页面即可恢复。

规则输出字段

      

        每条规则可独立设置 A / B：

        · 是否启用

        · 波形（持续 / 呼吸 / 潮汐 / 心跳 / 脉冲 / 渐强 / 渐弱 / 锯齿 / 随机 / 按摩）

        · 强度 0–200

        · 秒数（0 表示持续到条件不成立）


        A/B 的波形互不影响，设备层会按 25ms 粒度分别生成 B0 数据。

        强度最终仍受设备自身限制。

OCR（附赠功能）给 RPG Maker MV/MZ 之外的文字类游戏

      

        

          这是附赠功能，用于 RPG Maker MV/MZ 之外、无法安装插件的文字类游戏
          （Unity、独立 AVG 等）。原理是调用 Windows 自带 OCR 识别屏幕上的文字，
          不是 hook，所以有延迟，也会受字体、背景、文字速度影响。
        

        

          使用前请先安装系统 OCR 语言包：

          Windows 设置 → 时间和语言 → 语言 → 添加中文/日文/英文 →
          安装“光学字符识别”。

          识别语言列表只显示系统已安装的 OCR 语言。

          识别出的文字会作为【规则】里“OCR 文本”来源的输入；文字稳定约 2 帧后才会触发规则。
        


        

          OCR 有 1–3 秒延迟，快速滚动/逐字显示会漏读；请把游戏文字显示速度调快、自动翻页速度调慢。

          只支持关键词/正则规则，不支持变量、图标、颜色；需要游戏保持前台可见。
